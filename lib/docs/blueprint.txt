## 1) Obiettivo della migrazione

1. **Accuratezza** multilabel con recall alto (FN penalizzati > FP).
2. **Costo/latency** sotto controllo: SLM rapidi per i casi facili, **Heavy LLM** *solo se* A≠B.
3. **Auditabilità**: evidenze testuali con **quote + span** per ciascuna label (“why” breve, verificabile).
4. **Comparazione** corretta **OpenAI ↔ Apertus** (stessa pipeline, config diverse).
5. **Valutazione** finale con metrica ufficiale (già presente).

---

## 2) Nuova architettura (pipeline 1→10)

```
1) Text Cleaner
2) Language Router (opzionale)
3) Classifier-A (SLM, zero-shot)
4) Classifier-B (SLM, few-shot)
5) Disagreement Gate (se A≠B → Heavy)
6) Classifier-Heavy (LLM, solo su disaccordo)
7) Label Scorer (YES/NO logprobs su tutte le 8 label)
8) Evidence Checker (regole + micro-SLM opz. per quotes)
9) Label Finalizer (soglie, flag dubbi, cost/latency)
10) Logging / Metrics / Evaluation
```

## 5) Interfacce I/O (TypeScript) — **essenziali**

```ts
// types/pipeline.ts
export type Label =
  | "plan_contact"
  | "schedule_meeting"
  | "update_contact_info_non_postal"
  | "update_contact_info_postal_address"
  | "update_kyc_activity"
  | "update_kyc_origin_of_assets"
  | "update_kyc_purpose_of_businessrelation"
  | "update_kyc_total_assets";

export interface SampleIn {
  sampleId: string;
  path: string;
  rawText: string;
}

export interface CleanOut {
  sampleId: string;
  cleanText: string;
  stats: { charCount: number };
}

export interface RoutedOut {
  sampleId: string;
  textForModel: string;
  sourceLang: "en"|"de"|"it"|"fr"|"mixed";
  translated: boolean;
  translatorProvider: "supertext"|"none";
  routingHint: "original_en"|"translated_en";
}

export interface EvidenceItem {
  label: Label;
  quote?: string;                        // ≤ 140 char
  span?: { start: number; end: number }; // opz, validata poi
  hint?: string;                         // trigger id (es. "inherit")
}

export interface ClassifierOut {
  labels: Label[];
  evidence: EvidenceItem[];
  logitInfo?: { available: boolean };
  meta: { modelId: string; prompt: "zero_shot"|"few_shot"|"heavy" };
}

export interface GateOut {
  decision: "use_agreement" | "escalate_heavy";
  candidate?: { labels: Label[]; evidence: EvidenceItem[]; meta: any };
}

export interface ScorerOut {
  scoresYesNo: Partial<Record<Label, number>>; // 0..1
  meta: { scoringModel: string; calls: number; latencyMs: number };
}

export interface EvidenceCheckOut {
  verifiedLabels: Label[];
  perLabelConfidence: Partial<Record<Label, number>>;
  evidenceQuotes: Partial<Record<Label, EvidenceItem[]>>;
  issues: string[];
  explainabilityForAdvisor: Partial<Record<Label, string>>;
}

export interface FinalOut {
  labelsFinal: Label[];
  confidence: Partial<Record<Label, number>>;
  flags: string[]; // es. ["human_review_recommended"]
  summary: { modelsUsed: string[]; latencyMs: number; costEstimateUsd: number };
}
```

## 6) Orchestrator — flusso (pseudo-TS)

```ts
// lib/agents/orchestrator.ts
export async function runPipeline(sample: SampleIn, cfg: Config): Promise<FinalOut> {
  const cleaned = await textCleaner(sample);
  const routed  = await languageRouter(cleaned, cfg);

  const a = await classifierA(routed, cfg);   // SLM zero-shot
  const b = await classifierB(routed, cfg);   // SLM few-shot

  const gate = disagreementGate(a, b);
  const candidate =
    gate.decision === "use_agreement"
      ? gate.candidate!
      : await classifierHeavy(routed, cfg);   // LLM few-shot, solo su disaccordo

  const scores = await labelScorer(routed, cfg);  // YES/NO su tutte e 8 le label

  const verified = await evidenceChecker(
    { ...candidate, scoresYesNo: scores.scoresYesNo },
    routed,
    cfg
  );

  const final = await finalizer(verified, cfg);
  await logAndEvaluate(sample, a, b, gate, candidate, scores, verified, final, cfg);
  return final;
}
```

## 7) Prompt — Heavy LLM (few-shot) **concreto**

**prompts/prompt_heavy.txt**

```
You are a Swiss banking assistant. Classify client–advisor transcripts into one or more of:
["plan_contact","schedule_meeting","update_contact_info_non_postal",
 "update_contact_info_postal_address","update_kyc_activity",
 "update_kyc_origin_of_assets","update_kyc_purpose_of_businessrelation",
 "update_kyc_total_assets"].

Rules:
- Assign a label only if there is explicit, actionable evidence to log.
- Security verification alone (e.g., “confirm DOB/address”) is NOT an update.
- Return STRICT JSON only: {"labels":[...],"evidence":[{"label":"L","quote":"..."}]}.

```

> A/B usano: `prompt_zero_shot.txt` (regole secche) e `prompt_few_shot.txt` (2 mini-esempi mirati).

---

## 8) Label Scorer (YES/NO logprobs) — logica

* Per ciascuna delle 8 label: prompt **binario**
  “Answer with a single token: YES or NO. Does the transcript imply `<label>`?”
* Legge i **logprobs** del primo token (“YES”, “NO”) e calcola `P(YES)`.
* Se il provider non espone logprobs/logits → `scoresYesNo = null` e l’EC userà proxy (accordo A/B/Heavy + trigger + qualità quote).

---

## 9) Evidence Checker — compiti

1. **Verifica quote/span** (se presenti) o **estrazione** via regole → micro-SLM opzionale (una chiamata) solo se necessario.
2. **Trigger/anti-trigger** per ogni label (es. “verifica anagrafica” ≠ update).
3. **Fusione confidenza** (esempio):

   ```
   conf(L) = 0.55 * P_yesno(L)
           + 0.25 * trigger_score(L)
           + 0.15 * quote_quality(L)
           + 0.05 * agreement_weight(L)
   ```
4. **Explainability breve** per advisor: una frase con la **short quote**.

---

## 10) Finalizer — compiti

* Applica soglie: `default_conf = 0.60`, `kyc_conf = 0.70` (configurabili, considerando come è strutturata la funzione di evaluate).
* **Flags**: `human_review_recommended` se confidenza borderline o disaccordo A/B risolto a fatica.
* **Contabilità**: modelli usati, latenza totale, costo stimato.

## 13) Ottimizzazioni chiave

* **Costo/tempo**: SLM A/B → Heavy solo su disaccordo; Label Scorer low-temp logprobs.
* **Stabilità**: B few-shot complementa A zero-shot; Heavy few-shot su casi duri.
* **Audit & Compliance**: quote+span verificate; anti-trigger per evitare FP su verifiche anagrafiche.
* **Semplicità**: nessun ottimizzatore online; tutto in logging/metrics/evaluation.

---

## 14) Roadmap di migrazione (step-by-step)

1. **Cartelle & tipi**: creare nuovi file in `lib/agents/` e `types/pipeline.ts`.
2. **Provider**: implementare `llm/openai.ts` e `llm/apertus.ts` con interfaccia comune; `provider-router.ts`.
3. **Classifier A/B/Heavy**: spostare l’attuale `classifier` in A/B; creare Heavy con prompt few-shot.
4. **Disagreement Gate**: modulo semplice che confronta set(A.labels) vs set(B.labels).
5. **Label Scorer**: implementare YES/NO con logprobs/logits; fallback se non disponibili.
6. **Evidence Checker**: portare l’attuale `validation` → regole & quote; aggiungere micro-SLM extractor opzionale.
7. **Finalizer**: usare confidenze dall’EC + soglie config; aggiungere flags e cost accounting.
8. **Orchestrator**: aggiornare la catena 1→9.
9. **Logging/Metrics/Eval**: arricchire `eval_pipeline.ts` o creare `logAndEvaluate()`; salvare JSONL/summary.
10. **Runner confronto**: `compare/run_and_compare.ts` + `compare/charts.ts`.
